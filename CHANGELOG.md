# Changelog

## 1.0.1 — corrective release

Исправления, обнаруженные при реальном использовании станции.

### Исправлено
- Состав плейлиста снова отображается: API возвращает треки внутри
  `playlist.tracks`, frontend читает этот контракт. Ранее список выглядел пустым
  при заполненном плейлисте, из-за чего блокировалась кнопка «В эфир».
- Службы в настройках показываются по полю `unit` (Backend, Liquidsoap, Icecast)
  с фактическим состоянием, временем запуска и последней ошибкой.
- Статистика хранилища читает числовые поля: количество треков, размер музыки,
  обложки, база, свободное и общее место.
- Текущая позиция очереди приведена к одному контракту (`id` и `position_id`).
- Ссылки на трансляцию универсальны: основная — прямой MP3, без дублирующей
  «Minecraft / World Radio». HTTP-вариант появляется только при настроенном
  HTTP-маршруте.
- Статусы эфира отражают фактическое воспроизведение, а не только желаемое
  состояние: «В эфире» только при реальном треке, отдельные причины тишины.

### Добавлено
- Системный плейлист «Вся медиатека»: существует всегда, автоматически содержит
  все доступные треки, по умолчанию играет с перемешиванием и повтором.
- Собственные обложки плейлистов: загрузка, замена, возврат к автоматической.
- Массовый выбор треков («Выбрать все» для медиатеки и результатов поиска) без
  ограничения 50 записями, с честным результатом операции из backend.
- Запуск непустого плейлиста «В эфир» при остановленной станции и возврат
  «К автоматическому вещанию».
- Техническая тишина как штатный режим: станция запускается и с пустой
  медиатекой, музыка начинается автоматически после загрузки файлов.

### Исправлено в планировщике
- Цикл «Всей медиатеки» больше не «застревает» исчерпанным: источник использует
  сохранённые shuffle/repeat, повтор всего плейлиста запускает новый цикл.
- Явный запуск плейлиста начинает новый проход; новые треки попадают в текущий
  цикл; удалённые исчезают из очереди.
- Смена источника и перезапуск движка пересобирают очередь без ручных действий.

### Изменения API (совместимые по смыслу)
- `GET /api/admin/playlists/{id}` → `{playlist: {..., tracks, tracks_total}}`.
- `POST /api/admin/playlists/{id}/tracks` → `{added, skipped, unavailable, playlist}`.
- `GET /api/admin/tracks/ids` — идентификаторы для массового выбора.
- `POST|DELETE /api/admin/playlists/{id}/cover` — собственная обложка.
- `POST /api/admin/playlists/{id}/play` — запуск плейлиста в эфир.
- `GET /api/admin/links` → `{links: [...]}`.
- `GET /api/admin/services` → `{services: [{id, unit, label, state, state_label, ...}]}`.
- `GET /api/admin/storage` → числовые `tracks`, `bytes`, `cover_bytes`, `db_bytes`,
  `free_bytes`, `total_bytes`.
- `station.reason` в статусе и now-playing; `queue.current.id`.

### Миграция
- Неразрушающая миграция схемы (`user_version` 1 → 2): добавляется системный
  плейлист и колонка `system`, сбрасывается устаревшее состояние исчерпанного
  цикла. Музыка, пользовательские плейлисты, настройки, расписание, ротация и
  история сохраняются.
